Correction workflow

  1. Record the original system label and the correct label.
  2. Explain which rule or sequence proves the correction.
  3. Add when the same rule should not be used.
  4. Collect more than one example, including counterexamples.
  5. Review candidate rule changes against held-out examples before approving anything for live use.

Current learning instructions

These are the fixed safety and strategy guardrails for this learning workspace. Your new instructions can add detail but should not silently override these.

  • APA and SMC are evaluated together in context, not as independent labels that automatically create a trade.
  • Order Block qualification requires the project rule's associated three-candle FVG and appropriate displacement/structure context.
  • A breaker requires an OB to fail/pass through without initial respect, followed by a return that respects it from the opposite side after the relevant structural change.
  • Inducement is contextual and may invalidate an apparent OB; an inducement is not automatically an OB.
  • QML is optional and used as a reversal confirmation area; it is not present in every setup.
  • Never substitute generic head-and-shoulders for QML.
  • Minimum planned reward-to-risk is 1:3; no forced signal quota.
  • Not-triggered plans must not show running P/L or TP/SL progress before entry. Only confirmed entries become active.
  • No real broker order execution from this workspace.

Data, privacy & limits

  • Data is stored in this browser on this device using localStorage. It does not sync to another device or cloud.
  • Clearing browser site data can erase your learning records; export backups regularly.
  • Attached illustrations are stored as local data URLs only when the browser accepts the file size.
  • CSV replay is candle-by-candle and hides future candles from the chart. Do not infer a valid backtest from a single replay.
  • Saved rules are human-readable proposals. This release does not auto-edit the scanner or send trades.
